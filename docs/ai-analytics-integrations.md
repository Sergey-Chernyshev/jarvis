# Настройка аналитики и подключение других агентов

Аналитика Jarvis не привязана к имени пользователя, конкретному проекту или
модели. Все файлы и результаты остаются в профиле того пользователя, который
запустил приложение. Поддерживаются платформы самого Jarvis: macOS и Linux.

Открой **Аналитика ИИ → Настройки аналитики**. В обычном режиме достаточно
автоматического обнаружения Claude/Codex. Личный и рабочий Codex берутся из реестра
профилей в настройках агентов; подключённые узлы объявляют собственные профили.
Для отдельных файлов или собственного агента добавь источник и сохрани настройки.

## Источники

У источника есть стабильный `id`, формат, путь и переключатель включения:

```json
{
  "id": "my-agent",
  "format": "normalized",
  "path": "~/agent-events",
  "enabled": true
}
```

Путь может вести к каталогу JSONL-файлов или к одному файлу. Поддерживаются
абсолютные пути, `~/...` и `${HOME}/...`; это подстановка домашнего каталога,
не выполнение shell. Для репозитория, которого ещё нет в списке, можно указать
путь проекта вручную.

Доступны три адаптера:

| Формат | Что читать |
| --- | --- |
| `claude` | Нативные JSONL-трейсы Claude Code |
| `codex` | Нативные JSONL-rollout Codex |
| `normalized` | Единый формат событий Jarvis v1, описанный ниже |

Один файл не должен смешивать разные сессии. Для каждого сеанса создавай отдельный
файл. Стабильные ID источников отделяют одинаковые session ID разных систем;
один физический файл по нескольким путям не учитывается дважды.

Для нескольких аккаунтов добавь их каталоги отдельными источниками. Необязательно
переключать глобальный `CODEX_HOME` ради отчёта по второму профилю. Можно отключить
автообнаружение и оставить только явно выбранные источники. Недоступность
настроенного источника показывается как проблема покрытия, а не как отсутствие работы.

Подключение Cursor, OpenCode, собственного CLI или CI требует экспорта событий
в `normalized`, если их журналы не соответствуют двум нативным форматам. Jarvis
не заявляет автоматическую поддержку каждого закрытого формата и не пытается
угадывать его по произвольному тексту.

## Какие параметры можно менять

| Настройка | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `autoDiscover` | `true` | Читать включённые профили Claude/Codex и подключённые узлы |
| `limits.maxFiles` | 200 | Максимум файлов в одном отчёте |
| `limits.maxScanMiB` | 256 | Общий бюджет чтения трейсов |
| `limits.maxFileMiB` | 32 | Максимум чтения одного трейса |
| `limits.maxLines` | 200000 | Максимум JSONL-строк на файл |
| `limits.maxProjects` | 20 | Максимум Git-репозиториев в отчёте |
| `rules.idleCapMinutes` | 5 | Ограничение одного промежутка событий в прокси активности |
| `rules.contextWarningPct` | 85 | Порог сигнала о заполнении окна контекста |
| `rules.minModelSamples` | 5 | Минимум результатов на вариант модели для диагностического сравнения |
| `rules.harnessWeights` | Все три веса равны 1 | Вклад измерений в score |
| `rules.toolAliases` | `{}` | Соответствие имён инструментов каноническим операциям |
| `git.sourceExtensions` | Список популярных языков | Какие файлы включать в знаменатель Git-анализа |
| `git.excludeDirectories` | Зависимости и каталоги сборки | Исключения по компоненту пути |
| `git.excludeSuffixes` | `[".lock"]` | Исключения по окончанию имени |
| `git.excludeNameFragments` | `[".min.",".generated."]` | Исключения по фрагменту имени |
| `git.minMatchChars` | 12 | Минимальная длина строки для эвристики совпадений |
| `economics.currency` | `USD` | Валюта новых результатов |
| `economics.hourlyRate` | `null` | Стоимость часа по умолчанию; неизвестна до ввода |

Основные параметры редактируются формой; остальные доступны в расширенном JSON.
Настройки валидируются до сохранения. Недопустимые числа, неизвестная версия или
формат источника не заменяют работающую конфигурацию.

Вес `0` отключает измерение. При наличии данных:

```text
score = сумма(score измерения × его вес) / сумма весов применимых измерений
```

Неизвестные и отключённые измерения не входят в знаменатель. Хотя бы один вес
должен быть положительным. Названия весов:
`toolReliability`, `resultObservability`, `verificationAfterEdit`.
Сигналы промптинга в score не входят.

Меняя веса, пороги и состав источников, ты меняешь условия сравнения. Отчёт
содержит применённую конфигурацию и её `settingsHash`, чтобы результаты разных
пользователей или запусков можно было интерпретировать с учётом настроек.
Этот отпечаток — идентификатор настроек аналитики, а не доказательство одинакового
харнеса агента; его версию нужно записывать отдельно в результате задачи.

Можно загрузить значения по умолчанию, проверить их и затем сохранить. Кнопка
**Копировать настройки** позволяет перенести конфигурацию через расширенный JSON;
**Копировать JSON** в заголовке экспортирует сам отчёт. Пути каталогов нужно адаптировать
к другому компьютеру. Настройки сохраняются в
`$JARVIS_DIR/analytics-config.json` с правами `0600` и атомарной заменой.

Порог минимальной выборки является настройкой диагностики, а не уровнем
статистической достоверности. Даже при маленьком разрешённом пороге рекомендация
модели остаётся гипотезой для контролируемого сравнения.

## Единый формат JSONL v1

Каждая строка — отдельный JSON-объект. Общие поля:

```json
{
  "schemaVersion": 1,
  "eventId": "unique-event-1",
  "sessionId": "session-42",
  "timestamp": "2026-09-05T12:00:00Z",
  "cwd": "/absolute/path/to/project",
  "model": "provider/model-id",
  "type": "prompt",
  "text": "Исправить обработку пустого списка и проверить тестом"
}
```

`schemaVersion`, `eventId` и `sessionId` обязательны. `timestamp` — RFC 3339 или
миллисекунды Unix; отсутствующее время не выдумывается. `eventId` должен быть
уникален в сеансе; повторная доставка того же события не увеличивает метрики,
в том числе при другом порядке JSON-ключей. Повтор ID с конфликтующим содержимым
и несколько разных session ID в одном файле отклоняются.
`cwd` связывает события с локальным проектом. `model` — фактическая модель
на момент события, а не только последняя модель сеанса.

Поддержанные типы:

| `type` | Дополнительные поля |
| --- | --- |
| `prompt` | `text`: реальный запрос пользователя |
| `tool_call` | `callId`, `tool`, `args` |
| `tool_result` | `callId`, `status`: `success`, `error` или `unknown`; при наличии `exitCode` |
| `usage` | `requestId`, `inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`, `reasoningTokens` |
| `context_compaction` | Явное событие сжатия контекста |

`callId` обязателен для вызова и результата; `tool_result.callId` обязан совпадать
с исходным вызовом. `requestId` обязателен для usage. Статус означает
наблюдаемый результат инструмента, не принятие всей задачи. Не отправляй `success`
сразу после запуска фоновой команды: дождись её завершения или укажи `unknown`.
Не заменяй отсутствие результата нулевым exit code.

Событие usage описывает **один запрос**, не накопительный расход всей сессии.
`inputTokens` — некэшированный вход; чтение и запись кэша вынесены отдельно.
`reasoningTokens` является частью `outputTokens`, второй раз суммировать его нельзя.
Повторные/уточняющие usage одного `requestId` объединяются по максимуму каждого
счётчика, а не складываются. Для `normalized` обязательны оба неотрицательных
целочисленных счётчика `inputTokens` и `outputTokens`; отсутствие одного из них
не даёт известного расхода. Необязательные счётчики, если переданы, также должны
быть неотрицательными целыми числами.
Если usage не измерен, не отправляй выдуманные нули.

События не запускают команды и не меняют репозиторий. Они только описывают
произошедшую работу. Семантические оценки и статус принятия задачи из таких
событий автоматически не подставляются: результат записывает человек.

Минимальная пара инструмента:

```jsonl
{"schemaVersion":1,"eventId":"e1","sessionId":"s1","timestamp":1000,"cwd":"/path/to/repo","model":"my-model","type":"tool_call","callId":"c1","tool":"exec_command","args":{"cmd":"python -m unittest"}}
{"schemaVersion":1,"eventId":"e2","sessionId":"s1","timestamp":2000,"cwd":"/path/to/repo","model":"my-model","type":"tool_result","callId":"c1","status":"success","exitCode":0}
```

Это пример формата, не настоящая выполненная проверка. Для просмотра старого
примера выбери период **Всё**, поскольку timestamp 1000–2000 относится к 1970 году.

### Собственные имена инструментов

Если твой инструмент называется `terminal.run`, но использует канонические
аргументы `{"cmd":"..."}`, можно задать:

```json
{
  "rules": {
    "toolAliases": {
      "terminal.run": "exec_command"
    }
  }
}
```

В `normalized` классификация требует точного канонического имени или явно
настроенного алиаса. Одного совпадения окончания имени (например, `storage.Write`)
недостаточно. Алиас меняет классификацию, не преобразует произвольную структуру аргументов.
Например, для канонического `Write` нужны `file_path` и `content`, для `Edit` —
`file_path`, `old_string`, `new_string`. Если твой API устроен иначе, адаптируй
аргументы в экспортёре. Не называй оболочку с несколькими действиями одиночной
командой только ради высокого score: при неизвестных вложенных результатах
следует сохранить их непрозрачность.

## Перенос между людьми и командами

1. Согласуйте версию конфигурации, веса, фильтры исходников и рубрику приёмки.
2. На каждом компьютере настройте собственные пути источников; автоматическое
   обнаружение остаётся удобным вариантом по умолчанию.
3. Используйте одинаковые типы задач и отдельно фиксируйте версию харнеса агента.
4. Записывайте время и затраты в своей валюте: код — три заглавные латинские буквы,
   например USD, RUB, EUR, GBP, CNY, INR, JPY. Конвертации и смешивания валют нет.
5. Перед сравнением проверьте покрытие источников, usage, прямых инструментов и
   подтверждённых результатов. Не сравнивайте частичный захват с полным как
   одинаковые условия работы.

Текущая реализация — локальный отчёт каждого пользователя. Централизованного
сервера сотрудников, отправки данных руководителю или общего рейтинга людей
в ней нет. Для совместного разбора можно вручную копировать JSON отчёта; он
содержит пути, ID и введённые заметки, поэтому это не обезличенный экспорт.

Общий пользовательский гайд и формулы: [как работает аналитика](ai-analytics.md).
