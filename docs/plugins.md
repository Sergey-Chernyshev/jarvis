# Плагины Jarvis

Десктопный Jarvis — это **ядро плюс плагины**. Ядро умеет жизненный цикл,
безопасность, сущности и рамы интерфейса; всё остальное — способности, и каждая
способность оформлена как плагин. Наши собственные — тоже
(см. [спеку](superpowers/specs/2026-08-19-everything-is-plugin-design.md)).

Плагин — это **манифест плюс рантайм**.

## Два рантайма

| | **Встроенный** (`builtin`) | **Внешний** (`external`) |
|---|---|---|
| Кто | способности самого Jarvis | ваши интеграции, на любом языке |
| Форма | Rust-тип в `src-tauri/src/plugin/builtin/` | исполняемый файл |
| Канал | прямой вызов внутри процесса | JSON-lines по stdin/stdout |
| Права | наш код, гранта не получает | грант из манифеста, гейт на каждом вызове |
| Изоляция | **нет** | процесс: крэш не роняет Jarvis |

«Выключен» для встроенного значит «не держит ресурс и не отвечает на команды»,
а не «выгружен из памяти». Так честнее, и именно так это написано в UI.

## Установка внешнего плагина

```
~/.jarvis/plugins/<id>/
├── manifest.json
└── bin/plug          # исполняемый файл из entry.path
```

Jarvis сканирует каталог на старте. Каталог с непринятым манифестом не
пропадает молча: плагин появится в списке со статусом `error` и причиной.
Включается тумблером в настройках → «Плагины».

Готовый пример со всем протоколом — [`plugins/example-hello/`](../plugins/example-hello/).

## Манифест

```jsonc
{
  "id": "my-plugin",              // [a-z0-9-], он же ключ в settings.plugins
  "name": "Мой плагин",
  "version": "1.0.0",             // semver
  "description": "Что он делает",
  "icon": "blocks",               // имя иконки из набора UI
  "kind": "external",
  "entry": { "path": "bin/plug", "args": [] },   // только внутри каталога плагина
  "capabilities": ["read"],       // классы риска: read | control | settings
  "uses": ["sessions.list"],      // конкретные капабилити ядра
  "provides": [{ "kind": "vm", "attrs": ["state"] }],
  "consumes": [{ "plugin": "agent-vm", "kind": "vm" }],
  "defaultEnabled": false,
  "tray": true,
  "settings": [ /* схема → UI рисуется сам */ ],
  "commands": [ { "name": "go", "title": "Поехали" } ]
}
```

Манифест — **декларация желаний, а не прав**: он говорит, чего плагин просит.
Права выдаёт пользователь тумблером, а гейт сверяет каждый вызов. Класс `admin`
не выдаётся никому и молча отбрасывается.

### Схема настроек

Типы: `toggle`, `segmented`, `select`, `number`, `text`. Поля: `key`, `title`,
`hint`, `default`, `options` (`{value,label}`), `min`/`max`, `depends` (показывать,
только если другой ключ истинен). Ключ `enabled` принадлежит ядру — это тумблер
плагина. Значения живут в `~/.jarvis/settings.json` → `plugins.<id>`.

Если способности мало generic-панели, манифест может указать `"pane": "awake"` —
«мои настройки живут в такой-то существующей вкладке»; тогда вкладка «Плагины»
не дублирует их, а отсылает туда.

## Протокол трубы

Один кадр — одна строка JSON.

```
← {"event":"register","data":{"protocol":1,"pid":123}}   первым, иначе не живой
← {"event":"status","data":{...}}                        что показать в UI
← {"event":"tray","data":[...]}                          секция трея
← {"event":"log","data":"строка"}                        в ~/.jarvis/jarvis.log
→ {"id":1,"method":"go","params":{...}}                  команда из манифеста
← {"id":1,"ok":true,"value":{...}}
← {"id":1,"ok":false,"error":"почему"}
```

Правила, которые стоит знать заранее:

- **Handshake — 3 секунды.** Не прислал `register` — плагин прибит со статусом
  `error`. Мажор протокола не совпал — статус `incompatible`, перезапусков нет.
- **Команда — 10 секунд.** Просрочка = ошибка команды, но плагин остаётся жив.
- **Крэш** → перезапуск с backoff 1с → 60с. Пять падений подряд — перестаём
  поднимать (иначе вечный цикл), статус `error`.
- **Выключение** → SIGTERM, через 3 секунды SIGKILL, токен отзывается.
- **stderr** уходит в общий лог с префиксом `[plugin:<id>]`.
- Неизвестные события ядро игнорирует, неизвестные поля манифеста тоже —
  чтобы новый плагин работал на старом ядре и наоборот.

### Пункты трея

```jsonc
{"type":"label","text":"…"}
{"type":"action","id":"hi","text":"Поздороваться","cmd":"привет","args":{}}
{"type":"check","id":"a","text":"…","checked":true,"cmd":"set","args":{"auto":false}}
{"type":"submenu","text":"…","items":[…]}
{"type":"separator"}
```

`id` уникален внутри плагина, `cmd`+`args` — что позвать по клику (`cmd` по
умолчанию равен `id`). Ядро клик **не переводит**: пункт меню сам несёт своё
действие, поэтому в ядре нет таблицы «что значит эта кнопка».

## Как плагин говорит с ядром

Труба — это управление. За данными и действиями плагин ходит в
**capability-слой** по UDS `$JARVIS_SOCKET`, предъявляя `$JARVIS_TOKEN`:

```sh
curl --unix-socket "$JARVIS_SOCKET" -s http://localhost/capability \
  -H "x-jarvis-token: $JARVIS_TOKEN" \
  -d '{"id":"sessions.list","args":{}}'
```

Там стоит гейт: класс риска сверяется с грантом, side-effect'ы требуют
подтверждения пользователя, всё попадает в аудит. Второго пути в ядро нет и не
будет — именно поэтому канал управления и канал доступа разные.

`GET /capabilities` отдаёт список того, что доступно предъявителю токена.

## Встроенный плагин (для контрибьюторов)

Реализуйте `Plugin<Arc<Daemon>>` в `src-tauri/src/plugin/builtin/` и добавьте
одну строчку в `register_all`. Манифест собирается тем же `Manifest::parse` из
JSON-литерала — валидация у своих и чужих одна.

```rust
impl Plugin<Arc<Daemon>> for МойПлагин {
    fn manifest(&self) -> &Manifest { &self.manifest }
    fn start(&self, d: &Arc<Daemon>, _t: Option<&str>) -> Result<(), StartFail> { … }
    fn stop(&self, d: &Arc<Daemon>) { … }
    fn status(&self, d: &Arc<Daemon>) -> Value { … }
    fn tray(&self, d: &Arc<Daemon>) -> Vec<TrayItem> { … }
    fn call(&self, d: Arc<Daemon>, name: String, args: Value) -> CallFut { … }
}
```

Главное правило ядра — **INV-KERNEL**: в ядре нет ветвлений по идентификатору
плагина. Если для новой способности хочется дописать `match id` в `tray.rs`,
`ipc.rs` или `settings2.js` — это сигнал, что чего-то не хватает в контракте;
расширять надо контракт, а не ядро.

## Чего пока нет

Каталога и установки в один клик, подписи плагинов, авто-обновления,
UI-вкладов произвольным HTML, меж-плагинных `consumes`-грантов (объявить в
манифесте можно, фильтрация включается вместе со вторым плагином-потребителем).
Это принятые ограничения текущей версии, а не забытые задачи.
