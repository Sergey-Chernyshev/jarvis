### Две правки к фактам ниже (проверено по коду, а не по памяти)

- `backendSessionId` **публикуется** в entity `agent_run`
  (`run_supervisor.rs:1078`) — строка таблицы про «не публикуется» неверна.
  Наружу его не отдаёт только `runtime.runs`, и это намеренно (спека v2 §13.3).
- Транскрипты гостя **не мирроятся** на хост: `config_mirror.rs:926` исключает
  `sessions`. Поэтому VM-чат — отдельная строка списка, а не бейдж поверх
  строки истории; связь по `backendSessionId` нужна лишь чтобы не задвоить
  редкий пересекающийся случай.
- Дефолт VM 6/8 у старой VM пришёл от **другой версии `avm`**, а не от
  отсутствия секции `resources`. Вывод не изменился (явные ресурсы правильны),
  но причина другая.

## Цель одной фразой

Проект в Jarvis открывается как **список своих чатов**, а не как пульт
виртуалки; чат читается как разговор, а не как лог тулзов; VM на проект ровно
одна и стоит предсказуемых ресурсов; о завершении задачи приходит уведомление.

## Этапы

Порядок выбран так: сначала дешёвое и заметное, потом то, что требует нового
контракта данных.

### Этап 1 — чат читается как разговор

Проблема владельца: «очень криво отображается форматирование, много ненужных
тегов» + «тулзы мне не так важны, хотим видеть сам чат».

1. Вырезать служебные секции **из текста**, а не отбрасывать блок целиком:
   парные `<oai-mem-citation>…</oai-mem-citation>`, `<citation_entries>`,
   `<rollout_ids>`, плюс общий разбор по списку известных служебных корней.
   Полезная часть ответа и мусор живут в одном блоке — это ключевое.
2. Прогнать по реальным транскриптам (`~/.codex/sessions`) и по Claude, собрать
   таблицу «что встречается → что показываем».
3. Тулзы и команды свернуть в компактные chips; развёрнутый вид — по клику.
   В сводке хода тулзов быть не должно: там только саммаризация.

Критерии: на скриншоте владельца ни одного служебного тега; тест на каждый
класс тега; в сводке нет строк вида «выполняется команда…».

### Этап 2 — ресурсы VM предсказуемы

1. `PROJECT_SPEC` пишет явные `resources` (4 CPU / 4 GiB / 120 GiB по спеке).
2. Существующие VM не пересоздаём: показываем фактические ресурсы в
   environment popover и предупреждаем о расхождении.
3. GC кэша образов Lima с порогом и ручной кнопкой «освободить место».

Критерии: новая VM детерминированно 4/4/120; в UI видно фактический размер;
841 МБ кэша можно освободить, не удаляя VM.

### Этап 3 — уведомление о завершении задачи

1. Разделить «чат открыт» и «приложение в фокусе»: сейчас `is_focused`
   подавляет уведомление, даже когда пользователь смотрит другой проект.
2. Уведомление о завершении прогона ведёт прямо в этот проект/прогон.
3. Тест на каждый переход состояния: `working → completed`, `failed`,
   `interrupted`.

Критерии: задача завершилась при закрытом/другом экране — ровно одно
кликабельное уведомление; повторный poll того же состояния не шумит.

### Этап 4 — чаты внутри проекта (нужен контракт данных)

1. Публиковать `backendSessionId` в entity `agent_run` — сейчас он есть только
   в run_store плагина. Без этого «чаты проекта» не собрать.
2. Связать чат истории с прогоном VM по `backendSessionId` + `cwd`.
3. Экран проекта: список чатов (и VM-овских, и обычных),状态 каждого,
   вход в чат. Пульт VM убрать в environment popover.

Критерии: открываю проект → вижу свои чаты, а не панель VM; VM-чат и обычный
различимы бейджем; на один проект ровно одна VM (уже так, закрепить тестом).

### Этап 5 — синхронизация состояний

1. Инвалидация кэша терминала: не показывать «работает», если снимок
   протух или сессия мертва.
2. Подключить `stopAgentVmTerminal` (сейчас недостижим из UI) либо удалить.
3. Пересинхронизация после оптимистичных записей каталога проектов.

Критерии: карточка проекта не врёт после смерти сессии; ни одной висящей
кнопки; состояние сходится после ошибки.

## Правила работы

- Каждый этап — отдельный проверяемый коммит; ветка одна.
- Перед коммитом: `npm run test:ui`, `cargo test`, `npm run check:public`,
  `node scripts/check-tauri-acl.mjs`.
- **Не переформатировать** файлы: fmt в этом репо намеренно информационный.
  Правки вносить точечно, `git add` — только нужные файлы.
- В master не мержить: PR #70 остаётся на ревью владельца.
- Живую проверку UI объявлять как «собрано, тесты зелёные, нужен взгляд», а не
