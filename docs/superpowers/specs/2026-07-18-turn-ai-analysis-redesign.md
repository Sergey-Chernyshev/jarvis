# Карточка хода: ИИ-разбор результатов вместо фактовой сводки

Дата: 2026-07-18 · Статус: утверждён владельцем · Предыстория: chatsum v1
вернули (PR #60) с фактовой карточкой (короткая проза + чипы файлов + строка
команд + лог инструментов). Владелец: «вообще не то» — нужен **ИИ-разбор
результатов** между промптом и ответом, а не список действий.

## 1. Проблема

Текущая карточка хода фактоориентирована: `summary` — 2–5 сухих предложений
«что сделано», плюс на равных строка команд и tool-лог. Это «действия».
Владелец хочет обратного: развёрнутый **анализ результатов** хода — жанр
завершающего уведомления (`ai_toast_summary`: «что по сути изменилось и какой
результат»), но **сильно подробнее**, плюс виджеты изменённых файлов. Сырые
действия из карточки уходят (остаются под тумблером «Лента»).

## 2. UX карточки (режим «Сводка»)

Ход = промпт пользователя → [работа] → финальный ответ. Карточка заменяет
[работу] на ИИ-разбор:

1. **Разбор** — 1–3 абзаца живого ИИ-текста (markdown): что по сути делалось,
   к чему пришли, результат/эффект, оговорки и риски. Итоги тестов/команд
   вплетены в прозу, не отдельной строкой.
2. **Виджеты файлов** — чипы изменённых файлов с бейджами «создан/изменён»,
   клик → вьюер документа / таб «Изменения» (уже реализовано, §3 спеки
   2026-07-18-chat-summary-and-docs-design). Doc-файлы первыми.
3. **Ответ агента** — реальный финальный ответ под сворачиваемым
   `💬 Ответ агента ▾` (по умолчанию свёрнут; фокус на разборе, но ответ
   доступен дословно в один клик).
4. **Убрано из карточки**: отдельная строка команд и tool-лог (это «действия»).
   Сырую ленту хода по-прежнему открывает тумблер «Лента».

Живой ход стримится как раньше; по Stop, когда разбор готов, ход схлопывается
в карточку.

## 3. Данные и промпт

### 3.1 Схема карточки (turns.rs `TurnCard`)

- `summary: String` — теперь **развёрнутый разбор** (markdown, 1–3 абзаца).
- `files: Vec<CardFile>` — виджеты (path, note, kind), как есть.
- `reply: String` — **новое**: финальный ответ агента для сворачиваемого блока;
  заполняется из `facts.final_reply` при `parse_card` (не из LLM), режется
  `head_tail` до разумного бюджета.
- **Удаляются** `docs_digest` и `commands`: разбор поглощает их прозой.
  `#[serde(default)]` + бамп `PROMPT_VERSION` → старый кэш инвалидируется,
  проблем с десериализацией нет.

### 3.2 Промпт (turns.rs `build_prompt` / `PROMPT_HEAD`)

Инструкция меняется с «summary 2–5 предложений + факты» на: «Напиши
развёрнутый разбор результатов хода для человека, который хочет понять итог, не
читая сырую ленту. 1–3 абзаца: (а) что по сути делалось и зачем; (б) что
получилось — ключевые результаты, включая исход тестов/команд словами; (в)
оговорки/риски, если есть. По-русски, идентификаторы/пути/команды as-is. Только
факты из FACTS и текста хода — не выдумывай.» Вход модели (FACTS: файлы,
команды, финальный ответ, tool_log, доки) остаётся прежним — меняется только
формат выхода. Схема выхода: `{"analysis": string, "files": [{path, note}]}`.
`PROMPT_VERSION` → 2.

### 3.3 Детерминированный фолбэк

Без `claude`/квоты/по таймауту/битый JSON: карточка остаётся
детерминированной, но в новом духе — `summary` = сжатый финальный ответ
(`squeeze_reply`/`head_tail`), `files` из фактов, `reply` = финальный ответ.
Без выдуманного анализа; UI тот же.

## 4. UI (renderer.js / index.html)

- Разбор рендерится как markdown (уже так), стили под многоабзацный текст.
- Новый сворачиваемый блок `💬 Ответ агента` (`<details>`), тело = `card.reply`
  через `renderMarkdown`. Пусто → блока нет.
- Убрать рендер `docs_digest`-блока «Дока» и строки команд `tsum-cmds`.
- Чипы файлов + бейджи + дифф — без изменений.
- Контракт-тест `chat-contract.test.mjs` обновить: карточка содержит разбор и
  сворачиваемый ответ, не содержит строки команд/лога действий.

## 5. Что НЕ трогаем

- `ai_toast_summary`/уведомление о завершении — отдельный жанр (одно
  предложение для тоста/списка), остаётся как есть. Два разных LLM-вызова.
- Тумблер «Сводка/Лента», кэш `turnsum`, дисковый формат (версия инвалидирует).
- Вьюер документов и дифф (§3 предыдущей спеки).

## 6. Тестирование

- Rust: `build_prompt` содержит новую инструкцию и не просит строку команд
  отдельным полем; `parse_card` разбирает `analysis`→`summary`, заполняет
  `reply` из фактов, валидирует `files ⊆ facts`; фолбэк-карточка без LLM несёт
  сжатый ответ. Порт существующих turns-тестов под новую схему.
- UI: контракт-тест обновлённой поверхности; рендер сворачиваемого ответа.
- Живое: Stop при открытом чате → карточка-разбор; сворачивание ответа; чипы
  файлов → вьюер/дифф; тумблер «Лента» показывает сырьё.
