# Редизайн «Клевер» — единый визуальный язык всех окон

**Дата:** 2026-08-02
**Источник:** проект Claude Design «Jarvis Redesign.dc.html»
(`claude.ai/design/p/05731c2b-08dd-4d25-b2c9-a2ec1d06eb29`), финальный **Turn 14**
(экраны 14a–14h), краски — Turn 11 (11a–11c).

## Что изменилось

Приложение было тёмным стеклом поверх нативного вибранси. Стало — **бумажная
карточка**: непрозрачная поверхность, одна краска, монохромные точки-состояния.
Один язык на все четыре окна: панель, тосты, чат с агентом, онбординг.

Три правки макета, которые видно сразу:

* вместо невнятного «слушаю» внизу панели — понятная подпись про будящее слово
  («скажи «джарвис» — я услышу») и живая волна, которая горит, только когда
  детектор реально слушает микрофон;
* вместо денег справа внизу — **полоска лимита подписки** с окном до сброса
  («лимит 62% · до 14:30»); расход возвращается настройкой «Внизу панели»;
* реплики в чате — обе стороны одной колонкой с подписью «ты · 13:38», без
  пузырей: разговор, а не мессенджер.

## Правила языка

Из макета, в порядке важности:

1. **Одна бумажная карточка.** Никакого стекла и градиентов внутри продукта.
   Поверхность — `--paper`, форма — радиус 16, тень `--shadow-panel`.
2. **Одна краска.** Акцент живёт на действии и на том, кто ждёт. Всё
   остальное — серая шкала.
3. **Точки-состояния различаются формой и светом, не цветом.**
   работает — чернильная заливка; закончила — только контур; ждёт — краска;
   лимит — тусклая (ты не нужен, нужно время); спит — бледная.
4. **Ритм строк.** Строка сессии 46px, строка настройки 52px, шапка 56px,
   нижняя полоска 42px.
5. **Вложенные радиусы.** Внутренний радиус меньше внешнего ровно на отступ.
6. **Табличные цифры везде** — колонка не дёргается, когда число меняется.

### Токены

Смысловые (`--paper`, `--surface`, `--ink`, `--ink-mute`, `--accent`,
`--accent-soft`, `--fill-1..3`, `--line`, …) объявлены в `theme.css`. Там же —
**слой совместимости**: старые имена (`--text`, `--muted`, `--faint`, `--border`,
`--hairline`, `--working`, `--waiting`, `--done`, …) переопределены через новые,
поэтому встроенные стили в `renderer.js` / `settings2.js` / `voice-history.js`
подхватывают палитру сами. Новый код должен брать смысловые имена.

Нейтральные заливки: `rgba(255,255,255,…)` из тёмной темы больше не работают на
бумаге — вместо них `--fill-1` (наведение), `--fill-2` (подложка),
`--fill-3` (выключенный тумблер).

### Тема и краска

* `settings.json`: `theme` = `light` | `dark` | `auto`, `paint` = `clover` |
  `coal` | `raspberry`, `footerBottom` = `limit` | `spend`, `mode` = `overlay` | `window`.
* Переключаются в «Настройки → Вид».
* `settings_set` с ключом `theme`/`paint`/`mode` вызывает
  `windows::broadcast_appearance` — событие `appearance` уходит во все окна, и
  они перекрашиваются одновременно, без перезапуска.
* Нативный материал окна (`window_theme` в `windows.rs`) читается из настроек
  **на старте**. Панель непрозрачная, поэтому материал виден только по
  скруглённым углам; смена темы на лету перекрашивает CSS сразу, а материал —
  со следующего запуска.

## Проверка

Окна macOS-only, но `ui/` — обычные HTML+JS. Скриншот-прогон:

```
google-chrome --headless=old --screenshot --virtual-time-budget=6000 <page>
```

с подставным `window.__TAURI__` (фикстура вместо IPC). Так снимались 14a-14h,
обе темы и все три краски. Виртуальное время обязательно: страница держит
`setInterval`, и без него снимок ловится до того, как приедут данные.

## Оконный режим (14h)

Приложение живёт в двух раскладках, `settings.json` → `mode`:

* **`overlay`** (по умолчанию) — накладка ⌘J как была: поверх всего, на всех
  Spaces, без иконки в доке, прячется по клику мимо и по Esc.
* **`window`** — обычное окно из макета 14h: список слева (264px), диалог
  справа, лимит в титульной полосе. Тянется, сворачивается, живёт на обычном
  уровне, не исчезает от клика мимо, иконка в доке.

Разметка **одна и та же**. Режим переключает `data-mode` на `<html>`, и панель
пересобирается CSS-сеткой:

```
'titlebar titlebar'
'banner   banner'
'cmdrow   detail'     ← поиск в сайдбаре, справа — та же стопка видов
'tabs     detail'
'list     detail'     ← список выехал из .content и стал сайдбаром
'footer   footer'
```

Ради этого `.list` вынесен из `.content` и стал соседом: в накладке его
показывает/прячет `setView` (как раньше), в окне он видим всегда. Вкладки в
сайдбаре ложатся сеткой 2×2, шестерёнка уезжает в титульную полосу — в 264px
пять вкладок в строку не помещаются.

Что меняется в поведении (Rust):

| | накладка | окно |
| --- | --- | --- |
| уровень окна | `float_above_everything` (screen-saver level, все Spaces) | `float_normal` |
| клик мимо | прячет (`Focused(false)`) | ничего |
| Esc из списка | прячет | ничего (закрыть — ⌘W) |
| ⌘J при видимом окне | прячет | поднимает, если не в фокусе; прячет, если в фокусе |
| ⌘W / ⌘M / ⌃⌘F | — | закрыть (спрятать) / свернуть / фуллскрин |
| размер | `place_panel` под курсором | свой, помнится в `windowW`/`windowH` |
| док / ⌘Tab | нет (`ActivationPolicy::Accessory`) | есть (`Regular`) |

### Светофор и оконные привычки

Декораций нет в обоих режимах (`decorations(false)`) — кнопки нарисованы сами,
но ведут себя как системные:

* **красная** — `winClose` → `close()`; `CloseRequested` перехвачен, окно просто
  прячется, демон живёт дальше;
* **жёлтая** — `winMinimize`;
* **зелёная** — фуллскрин (`setFullscreen`), с **Alt** — зум по содержимому
  (`toggleMaximize`), ровно как в macOS;
* цвет горит только у активного окна (`data-win-focus` на `<html>`), значки
  ✕ − ⤢ проявляются при наведении на группу;
* двойной клик по титульной полосе — зум; тянется она за пустое место
  (`data-tauri-drag-region` на самой полосе и на распорке).

Своего меню у приложения нет, поэтому системные сочетания не привязываются
сами — **⌘W**, **⌘M** и **⌃⌘F** повешены руками в `renderer.js` (только в
оконном режиме).

Два места, где это могло молча не работать, и что с ними сделано:

* `float_normal` раньше ставил `collectionBehavior = 0`, что снимает
  `NSWindowCollectionBehaviorFullScreenPrimary` — без него AppKit не пускает
  окно в фуллскрин. Теперь ставится `Managed | ParticipatesInCycle |
  FullScreenPrimary`, а в стайл-маску добавляется `Resizable` (без неё
  фуллскрина у borderless-окна тоже нет).
* при возврате в накладку окно сначала выходит из фуллскрина
  (`set_fullscreen(false)`), иначе накладка осталась бы во весь экран.

В фуллскрине карточка теряет скругление и тень (`data-fullscreen` на `<html>`),
иначе по углам экрана видны прорези. Анимация появления (`.panel.entering`)
в оконном режиме выключена — окно не должно «выпрыгивать» при каждом показе.

Переключение применяется на лету (`windows::apply_mode`): свойства окна
меняются, CSS перестраивается по событию `appearance`. Единственное, что ждёт
перезапуска, — иконка в доке: `ActivationPolicy` ставится на старте.

## Что осталось на потом

* `Window::set_theme` на лету — нативный материал сейчас применяется со
  следующего запуска (см. выше).
* `ActivationPolicy` на лету — иконка в доке появляется со следующего запуска.
