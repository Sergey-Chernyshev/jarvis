# Страница «Среды» и настройки Agent VM

Дата: 2026-08-07

Основа: [`2026-07-28-agent-vm-project-runtime-design.md`](2026-07-28-agent-vm-project-runtime-design.md)

Статус: v1, дизайн зафиксирован на макетах и утверждён владельцем

## 1. Задача

Сегодня у Agent VM нет места, где видно **что происходит** и **что агент внутри
VM знает обо мне**. Состояние живёт в per-project popover, а перенос конфигов не
показан нигде, хотя именно он объясняет самый частый вопрос: «почему агент в VM
ведёт себя иначе, чем на хосте».

Спека вводит два экрана:

1. **«Среды»** — состояние машин, обзор их файловой системы, свод переноса.
2. **Вкладка «Среды» в настройках** — глобальные значения, влияющие на все VM.

Разделение следует §11 основной спеки: Agent VM не получает отдельный
«технический мир». Наблюдение живёт своей страницей, настройки — там же, где все
остальные настройки Jarvis, теми же строками, что и «Под капотом».

### 1.1 Что здесь не решается

- Удаление VM. `avm delete` существует, но `lifecycle_spec`
  (`plugins/agent-vm/src/service.rs:829`) допускает только
  `start|stop|restart|recreate`. Расширять список эта спека не предлагает.
- Пауза/suspend. Ни в Jarvis, ни в `avm` их нет. См. §4.2.
- Правка allowlist переноса. Списки захардкожены в `config_mirror.rs` намеренно.

## 2. Экран «Среды»

Вкладка верхнего уровня рядом с «Чаты», «Проекты», «Статистика», «Голос».

```text
Изолированные среды                          Очистить кэш · 841 МБ
1 из 8 работает · 10.2 ГБ на диске

● sup       6 cpu  3.1/8 ГиБ  6.3 ГБ  2:14 ч    [Файлы] [Перезапустить] [Выключить]
○ ticksly   4 cpu  4 ГиБ  3.9 ГБ  остановлена   [Файлы] [Запустить]

┌ ✓ Опыт и настройки перенесены в VM                                        ⌄ ┐
│   41 файл · снимок обновляется при каждом запуске                           │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 Строка машины

Одна VM — одна строка, без карточек и полосок загрузки.

- Точка состояния: `--accent` для `running`, приглушённый `--ink-faint` для
  `stopped`, `--danger` для `error`.
- Метрики компактным блоком: число обычным весом, единица тонкой подписью
  (`6 cpu`, `3.1/8 ГиБ`, `6.3 ГБ`, `2:14 ч`). Полная расшифровка — в `title`
  каждого числа. Развёрнутая фраза («6 CPU · 3.1 из 8 ГиБ · 2 ч 14 мин»)
  отвергнута: её приходится читать, а не считывать.
- Действия проявляются на `:hover` и `:focus-within`; в покое строка молчит.
- Для `stopped` вместо uptime — слово состояния, метрики показывают
  выделенные ресурсы.

### 2.2 Свод переноса

Свёрнут по умолчанию: итог одной строкой. Раскрывается по клику в таблицу, где
у каждой строки свой знак:

| Знак                     | Смысл                     | Пример                                      |
| ------------------------ | ------------------------- | ------------------------------------------- |
| стрелка, `--accent`      | перенесено                | Память проекта · 28 файлов                  |
| треугольник, `--warn`    | перенесено с оговоркой    | MCP-серверы · 5 из 6, postgres-local не едет |
| перечёркнутый круг, тихий| не переносится            | Хуки · зовут команды хоста, которых в VM нет |

Прошлая версия разделяла список на секции «уехало» и «не переносится» — вторая
читалась как продолжение первой. Знак в строке снимает двусмысленность.

Внизу раскрытия — объяснение механики, самое важное на экране:

> Это копия, а не общая папка: агент внутри VM видит те же файлы, но его правки
> на хост не вернутся и заменятся при следующем запуске. Исключение — каталог
> проекта: он общий на запись в обе стороны.

### 2.3 Длинные списки

Навыков может быть сотня (у владельца 104). Список строками растянул бы страницу
на экраны, поэтому:

- чипы в несколько рядов, область прокрутки ограничена `max-height: 128px`;
- поле поиска с плейсхолдером «Поиск среди N навыков»;
- счётчик «показаны 16 из 104» либо «найдено N» при активном поиске.

Проверено стресс-тестом: 104 чипа дают 1245px контента, обрезанного до 128px;
карточка не распухает.

### 2.4 Подсказки у действий

Действие, чья цена не видна из названия, получает подсказку — не `title`
(появляется с задержкой, без переносов, вне нашей типографики), а собственный
элемент, раскрывающийся по `:hover` и `:focus-within`.

Формат: заголовок, затем строки с `✓` (что сохранится) и `✗` (что будет
потеряно), затем итог. **Перечисляя потери, обязательно называем и то, что
сохраняется** — иначе список потерь читается как полный список последствий.

Подсказки нужны у: «Очистить кэш», «Выключить», «Перезапустить»,
«Добавить папку».

## 3. Экран файлов VM

Открывается кнопкой «Файлы» на строке машины. Данные строятся от выбранной
машины: у каждой свой `hostPath` и своё имя.

### 3.1 Карта

```text
← ticksly                                          Открыть терминал
  файлы внутри VM · 3.9 ГБ из 120 ГиБ

Общие папки с хостом
  ~/ticksly              → /home/…guest/ticksly-…    чтение и запись   →
  ~/.config/agent-vm     → /mnt/host/agent-vm        только чтение
  + Добавить папку

Домашний каталог агента
  .claude/     снимок     →
  .codex/      снимок     →
  .jarvis-vm/  служебное
```

Два монтирования — ровно то, что в `lima.yaml`: каталог проекта на запись и
`~/.config/agent-vm` только на чтение. Дополнительные папки из `.agent-vm.yaml`
показываются там же с крестиком снятия.

### 3.2 Обход по файлам

Клик по строке с папкой открывает её содержимое. Навигация:

- хлебные крошки `sup › src › backend`, любой сегмент возвращает на свой
  уровень, крестик закрывает обзор;
- папки идут перед файлами — список читается как дерево;
- у файла справа размер, у папки — стрелка входа.

Пустое состояние: «Пусто или не прочитано» с пояснением, что содержимое читается
из работающей VM.

### 3.3 Ограничения монтирования

Показываются в подсказке «Добавить папку», а не всплывают ошибкой после выбора:

- папка внутри проекта — сразу, на чтение и запись;
- папка вне проекта требует явного разрешения (`service.rs:912-917`);
- `.ssh`, `.claude`, `.codex`, `.aws`, Keychains и прочие из
  `PROTECTED_ACCOUNT_MOUNT_DIRS` (`service.rs:51-65`) закрыты навсегда;
- не больше 16 дополнительных папок (`inventory.rs:10`).

## 4. Точность формулировок

### 4.1 Перенос — это снимок, а не монтирование

`~/.claude` и `~/.codex` в VM **не монтируются**. `ConfigMirror` собирает tar и
распаковывает его в гостя при каждом bootstrap. Интерфейс обязан говорить
«снимок», «копия», «перенесено» — но не «примонтировано».

### 4.2 «Остановить» → «Выключить»

`stop` вызывает `avm stop` → `limactl stop`, то есть полное завершение работы
гостевой ОС. Ни `suspend`, ни `pause`, ни снапшота памяти в проекте нет.
Слово «Остановить» обещает продолжение с того же места, которого не будет.

Подсказка обязана содержать все четыре факта:

- машина и её диск останутся — ничего не удаляется;
- файлы проекта сохранятся: папка общая с хостом;
- процессы и dev-серверы внутри погибнут;
- следующий запуск — загрузка системы с нуля.

При активном прогоне агента выключение требует подтверждения: строка на месте
превращается в вопрос «Выключить sup? Агент сейчас работает — прогон
прервётся». Модальное окно не используется: вопрос локальный.

По той же причине настройка автоостановки называется **«Выключать
простаивающие»**, а не «Останавливать», и по умолчанию выключена — таймер
однажды убьёт долгоживущий dev-сервер (основная спека, §14).

## 5. Вкладка «Среды» в настройках

Встаёт в `NAV` (`ui/settings2.js:725-738`) после разделителя, рядом с «Под
капотом». Использует существующие примитивы: `drow`, `dgroup`, `dsection`,
`toggle`, `segmented`, `skelGroup`.

| Группа        | Строка                                | Контрол                       |
| ------------- | ------------------------------------- | ----------------------------- |
| Память        | Память проектов Claude                | Только свой / Все             |
| Память        | Память Codex                          | значение «целиком»            |
| Новые машины  | Процессоры                            | 2 / 4 / 8                     |
| Новые машины  | Память                                | 4 / 8 / 16 ГиБ                |
| Новые машины  | Диск                                  | значение                      |
| Поведение     | Поднимать закреплённые VM при старте  | тумблер                       |
| Поведение     | Выключать простаивающие               | Никогда / 30 мин / 2 ч        |

Настройки «Новых машин» применяются при создании VM и не трогают существующие —
это сказано в пояснении строки, а не оставлено на догадку.

## 6. Починка переноса памяти Codex

Отдельный пункт, не косметический: сейчас часть накопленного опыта теряется.

`config_mirror.rs:123-148` переносит `MEMORY.md` и `memory_summary.md`, но **не
переносит**:

| Файл                                    | Размер            |
| --------------------------------------- | ----------------- |
| `~/.codex/memories/raw_memories.md`     | 200 КБ            |
| `~/.codex/memories/rollout_summaries/`  | 344 КБ, 39 файлов |
| `~/.codex/memories/extensions/`         | 20 КБ             |

Вся память Codex — 768 КБ при `MAX_MIRROR_TOTAL_BYTES` = 64 МБ, запас
двукратно избыточен. Добавляем все три в списки одиночных файлов и деревьев.

Память Claude по проектам переносится корректно: ключ каталога переписывается с
host-пути на guest-путь (`config_mirror.rs:97-111`), иначе Claude не нашёл бы её
как «свою». Проверено на живых данных: `-Users-se-chernyshev-jarvis`, 28 файлов.

## 7. Чего нет в бэкенде

Экран опирается на данные, которых сегодня не существует. Каждый пункт — работа,
а не отображение.

| Нужно                        | Сейчас                                              |
| ---------------------------- | --------------------------------------------------- |
| CPU-загрузка гостя           | нет; грепы по `plugins/agent-vm/src/` пусты          |
| Фактическая RAM гостя        | нет                                                  |
| Uptime VM                    | нет; `createdAt` есть в YAML, но `VmRecord` не парсит |
| Реальный размер диска        | `dir_size` даёт apparent size sparse-файла: 80 ГиБ вместо 6.3 ГБ |
| Размер per-VM                | только сумма по всему `lima_home`                    |
| Листинг каталогов гостя      | нет; нужен `limactl shell ls` с разбором             |
| Правка ресурсов              | нет ни IPC, ни функции записи Record                 |
| Автоостановка по простою     | нет таймера и счётчика простоя                       |
| Хранилище настроек VM        | блок `plugins.agent-vm` в `settings.json` не заведён |

Порядок работ: сначала то, что уже есть в IPC (список машин, состояния,
`releaseCache`, автостарт), затем реальный размер диска, затем листинг файлов,
затем метрики.

## 8. Порядок реализации

1. **Починка памяти Codex** — три строки в `config_mirror.rs` + тесты. Не
   зависит от UI, чинит потерю данных.
2. **Экран «Среды»** на существующих IPC: список машин из `runtime.inventory`,
   состояния, `runtime.stop/restart/ensure`, `runtime.releaseCache`. Метрики,
   которых нет, не показываем вовсе — не заглушками.
3. **Вкладка настроек** + блок `plugins.agent-vm` в `settings.json`.
4. **Реальный размер диска**: `du`-подобный обход вместо `len()`, per-VM.
5. **Листинг файлов** гостя и экран обхода.
6. **Метрики** CPU/RAM/uptime.

Шаги 1-3 самодостаточны и дают рабочий экран. 4-6 наращивают точность.

## 9. Проверка

- Перенос памяти Codex: тест на файл и на дерево, проверка попадания в снимок.
- Экран при нуле машин, при одной, при восьми (лимит `MAX_ACTIVE_VMS`).
- Список навыков при 104 элементах: страница не растягивается, поиск фильтрует.
- Выключение при активном прогоне: подтверждение обязательно.
- Файлы спящей машины: пустое состояние с объяснением, не ошибка.
- `prefers-reduced-motion`: анимации подсказок и раскрытий выключены.
