# Jarvis UI Next: функциональный инвентарь и parity-чеклист MVP

**Дата:** 2026-08-07  
**Статус:** baseline зафиксирован; browser MVP реализован, parity-аудит продолжается  
**Источники:** действующий `ui/`, `http://localhost:8777/unified.html`,
`http://localhost:8777/vmset.html`

## 1. Зачем нужен этот документ

React-прототип — не концепт одного экрана и не набор несвязанных мокапов. Это
кликабельная браузерная версия всего Jarvis UI, на которой можно проверить
информационную архитектуру, переходы, состояния, анимации и будущий typed IPC.

Редизайн может менять композицию, иерархию и визуальный язык, но не удаляет
существующие пользовательские возможности. Для MVP «функция сохранена»
означает:

1. у неё есть понятный вход в интерфейсе;
2. основной сценарий можно пройти на моковых данных;
3. loading, empty, success и error состояния представлены там, где они
   существуют в реальном приложении;
4. действие даёт видимый результат: меняет состояние, открывает панель,
   показывает прогресс, подтверждение или уведомление;
5. будущий backend-вызов изолирован за `JarvisClient`, а не зашит в компонент.

### Состояние browser MVP на 2026-08-07

Реализован отдельный `ui-next/` на React, strict TypeScript, Zustand, Motion и
Lucide. В браузере доступны все основные разделы, настройки, Agent VM,
environment/files, чатовые оверлеи, onboarding, notification preview и voice
HUD. Все они используют один typed `JarvisClient` и mock fixtures.

После первого визуального прохода настройки возвращены к проверенной геометрии
legacy `ui/settings2.js`: sidebar 248 px, строки 14/12.5 px и padding 15×16 px.
`Внешний вид` добавлен первым разделом. Исправлен layout-контракт оболочки:
опциональный config banner больше не растягивает footer вместо контента.

До production parity остаются именно интеграционные и hardening-задачи:

- нативные Finder/editor/terminal/clipboard действия пока дают mock feedback;
- Tauri client и generated Rust bindings ещё не подключены;
- long-list virtualization, полноценный Markdown renderer и drag-and-drop
  требуют production-реализации;
- отдельные loading/error fixtures и полный keyboard/a11y проход должны быть
  закрыты Playwright/WebKit тестами;
- производительность ещё не измерена внутри настоящего Tauri WebView.

Чекбоксы ниже остаются acceptance checklist: они закрываются только после
ручного browser-прохода и затем повторно после подключения Tauri, а не по факту
наличия похожего компонента.

## 3. Redesign constraints

- [ ] Сохраняется узнаваемый язык текущих страниц: Golos Text, компактность,
  paper surface, один акцентный «чернильный» цвет, монохромные статусы.
- [ ] Redesign улучшает иерархию: меньше визуального шума, яснее primary action,
  крупные состояния VM, спокойные списки.
- [ ] Нет градиентного «AI dashboard» и случайного набора карточек.
- [ ] Иконки из единой stroke-системы, без emoji и текстовых суррогатов.
- [ ] Motion объясняет изменение состояния: shared layout, раскрытие панелей,
  list stagger только при первом входе, progress и state transitions.
- [ ] Анимация не перезапускается при каждом локальном клике.
- [ ] Никаких `transition: all`.
- [ ] Интерактивные цели не меньше 32×32 px, видимый focus ring.
- [ ] Макет остаётся рабочим от 900×650 и комфортным на 1280×820.

## 4. Архитектурный parity-чеклист

- [ ] React + strict TypeScript без `any`.
- [ ] Все доменные сущности имеют discriminated unions.
- [ ] Компоненты не импортируют Tauri API напрямую.
- [ ] `JarvisClient` задаёт typed commands/events.
- [ ] `MockJarvisClient` реализует тот же интерфейс и задержки/ошибки.
- [ ] Mock fixtures отделены от компонентов.
- [ ] URL route можно открыть напрямую.
- [ ] Feature boundaries соответствуют будущей миграции.
- [ ] Перерисовки изолированы по feature/store selector.
- [ ] Большие списки не пересобирают весь app shell.
- [ ] Ошибки представлены в state-модели, а не через случайные DOM-вставки.

## 6. Known gaps

На старте реализации пусто. Если часть поведения невозможно честно показать без
нативного macOS API, в MVP остаётся интерактивный mock state и здесь фиксируется
только отсутствие реального side effect. Сам UI и сценарий не вырезаются.
